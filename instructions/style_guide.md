## 2. Logo Specifications

### 2.1 Primary Logo (Wordmark)

The primary logo is a typographic wordmark using the brand name in the primary blue color.

```
┌─────────────────────────────────────────┐
│                                         │
│    De Kunst van Werken                  │
│    ─────────────────────                │
│    [Primary Blue #004a99]               │
│                                         │
└─────────────────────────────────────────┘
```

**Specifications:**
- Font: Segoe UI Bold (or fallback: Tahoma Bold)
- Weight: 700 (Bold)
- Letter-spacing: Normal
- Case: Title Case

### 2.2 Logo Variations

| Variation | Use Case | Colors |
|-----------|----------|--------|
| Primary (Full Color) | Standard use on light backgrounds | Primary Blue on White |
| Reversed | Use on dark backgrounds | White on Primary Blue |
| Monochrome (Dark) | Single-color print applications | Black (#000000) |
| Monochrome (Light) | On dark single-color print | White (#FFFFFF) |

### 2.3 Clear Space Requirements

**Minimum clear space** around the logo ensures visibility and impact.

```
         ┌─────────────────────────────┐
         │     X                       │
    X    │  De Kunst van Werken       │    X
         │                     X       │
         └─────────────────────────────┘
                      X

X = Height of lowercase "e" in the wordmark
```

**Rule:** Always maintain a clear space equal to the height of the lowercase "e" on all sides of the logo.

### 2.4 Minimum Size Requirements

To ensure legibility, never use the logo smaller than:

| Medium | Minimum Size |
|--------|--------------|
| **Web/Digital** | 72px width (retina displays may require 144px) |
| **Print** | 1 inch (25.4mm) width |
| **Favicon/Small Icon** | Use abbreviated "DKvW" or icon-only version |

### 2.5 Logo Don'ts

❌ **Never:**
- Stretch or distort the logo proportions
- Rotate the logo at any angle
- Apply drop shadows or outer glows
- Change the font or typography
- Place on busy backgrounds without sufficient contrast
- Use unapproved colors
- Add outlines or borders
- Alter the spacing between words

### 3.3 Color Usage Ratios

For a balanced visual hierarchy:

```
┌─────────────────────────────────────────────────────────┐
│  PRIMARY BLUE  │  WHITE/LIGHT BG  │  ACCENT  │ TEXT    │
│     20-30%     │      50-60%      │   5-10%  │ 15-20%  │
└─────────────────────────────────────────────────────────┘
```

### 3.4 Forbidden Color Combinations

❌ **Never use:**
- Orange text on blue background (poor contrast)
- Light blue text on white background (accessibility fail)
- Primary blue text on dark backgrounds without inversion
- Gradients mixing more than 2 brand colors
- Neon or saturated variants of brand colors

✅ **Always ensure:**
- Minimum 4.5:1 contrast ratio for normal text
- Minimum 3:1 contrast ratio for large text (18px+)
- Test all combinations with WCAG contrast checkers

font-family: 'Segoe UI', Tahoma, Geneva, Verdana, sans-serif;

| **H3** | 28px (1.75rem) | 22px (1.375rem) | 600 (SemiBold) | 1.3 | Primary Blue |

|------|------|--------|-------------|-------|

### 4.3 Web-Safe Fallback Stack

If Segoe UI is unavailable, the browser will cascade through:

1. **Segoe UI** (Primary - Windows)
2. **Tahoma** (Fallback - Windows/Mac)
3. **Geneva** (Fallback - Mac)
4. **Verdana** (Wide compatibility)
5. **sans-serif** (System default)

### 4.4 Print & Merchandise Typography

For physical applications where Segoe UI may not be available:

| Application | Recommended Font | Alternative |
|-------------|------------------|-------------|
| **Business Cards** | Segoe UI (if licensed) | Open Sans |
| **Large Format Print** | Segoe UI Bold | Roboto Bold |
| **Embroidery (Small)** | Arial Bold | Helvetica Bold |
| **Embroidery (Large)** | Segoe UI Bold | Open Sans Bold |
| **Screen Printing** | Any sans-serif with clean lines | - |

**Note:** For merchandise requiring font licensing, **Open Sans** (Google Fonts, SIL Open Font License) is the approved free alternative.

### 4.5 Typography Don'ts

❌ **Never:**
- Use decorative or script fonts for brand materials
- Set body text smaller than 14px
- Use more than 2 font weights on a single page
- Apply text effects (shadows, outlines, emboss)
- Stretch or compress text
- Use all-caps for more than 3 consecutive words

- **Health & wellness** - Ergonomic workspaces, employee wellbeing

Apply a subtle overlay to align photos with brand colors:

```css

background: linear-gradient(
    rgba(0, 74, 153, 0.8),  /* Primary Blue at 80% opacity */
    rgba(0, 74, 153, 0.8)
), url('image.jpg');
```

### 5.2 Icon Style

| Attribute | Specification |
|-----------|---------------|
| **Style** | Line icons (outlined, not filled) |
| **Stroke Width** | 1.5-2px |
| **Corner Radius** | Slightly rounded (2-4px) |
| **Color** | Primary Blue or Text Dark |
| **Size Grid** | 24px × 24px base, scalable |

- Feather Icons
- Heroicons (outline)
- Phosphor Icons

### 5.3 Illustration Guidelines

If custom illustrations are needed:

- **Style:** Flat design with minimal gradients
- **Colors:** Use brand palette only
- **Complexity:** Simple, clean shapes
- **Human figures:** Abstract/simplified, inclusive representation

### 5.4 Graphics Don'ts

❌ **Never:**
- Use stock photos with obvious watermarks
- Include photos with competing brand logos visible
- Use overly saturated or filtered images
- Mix illustration styles within the same project
- Use clip art or dated graphics

## 8. Accessibility Standards

### 8.1 WCAG 2.2 Compliance (2026)

All digital properties must meet **WCAG 2.2 Level AA** standards.

#### Key Requirements

| Requirement | Standard | Our Compliance |
|-------------|----------|----------------|
| **Color Contrast (Normal Text)** | 4.5:1 minimum | ✅ Primary Blue on White = 7.2:1 |
| **Color Contrast (Large Text)** | 3:1 minimum | ✅ All combinations pass |
| **Focus Indicators** | Visible focus states | ✅ Orange outline on focus |
| **Target Size** | 24×24px minimum | ✅ Buttons meet requirement |
| **Motion** | Respect prefers-reduced-motion | ⚠️ Implement media query |

### 8.2 Color Contrast Ratios

| Combination | Ratio | WCAG AA | WCAG AAA |
|-------------|-------|---------|----------|
| Primary Blue on White | 7.21:1 | ✅ Pass | ✅ Pass |
| Text Dark on White | 10.69:1 | ✅ Pass | ✅ Pass |
| White on Primary Blue | 7.21:1 | ✅ Pass | ✅ Pass |
| Orange on White | 2.95:1 | ❌ Fail | ❌ Fail |
| Orange on Dark Blue | 4.58:1 | ✅ Pass | ❌ Fail |

**Important:** Never use Accent Orange for body text. It is only for decorative elements and interactive components where additional context (icons, hover states) provides meaning.

### 8.3 Accessible Design Practices

1. **Never rely on color alone** to convey information
2. **Provide text alternatives** for all images
3. **Ensure keyboard navigation** works on all interactive elements
4. **Use semantic HTML** (headings, landmarks, labels)
5. **Test with screen readers** (NVDA, VoiceOver)

## 9. Schema.org Structured Data

### 9.1 Overview

**Schema.org** is a collaborative vocabulary used to add structured data to web pages. Search engines like Google, Bing, and DuckDuckGo use this data to understand your content better, which can result in:

- **Rich snippets** in search results (star ratings, business hours, etc.)
- **Knowledge panel** information
- **Better SEO** through improved content understanding
- **Voice search** compatibility

For De Kunst van Werken, implementing proper Schema.org markup is essential for establishing credibility as a professional Arbo (occupational health) service provider.

### 9.2 Implementation Format

Always use **JSON-LD** (JavaScript Object Notation for Linked Data) format. Place the script in the `<head>` section of each page.

```html
<script type="application/ld+json">
{
    "@context": "https://schema.org",
    "@type": "...",
    ...
}
</script>
```

### 9.3 Required Schema Types

Every page on dekunstvanwerken.nl should include at minimum:

| Schema Type | Purpose | Pages |
|-------------|---------|-------|
| **Organization** | Core business identity | All pages (in header) |
| **WebSite** | Site-wide search and navigation | Homepage only |
| **ProfessionalService** | Business listing for local SEO | Homepage, Contact |
| **Service** | Individual service descriptions | Service pages |
| **BreadcrumbList** | Navigation hierarchy | All pages except homepage |
| **ContactPage** | Contact form identification | Contact page |
| **FAQPage** | FAQ content (if applicable) | FAQ sections |

### 9.7 Testing & Validation

Always validate your structured data before publishing.

#### Testing Tools

| Tool | URL | Purpose |
|------|-----|---------|
| **Google Rich Results Test** | https://search.google.com/test/rich-results | Primary validation tool |
| **Schema Markup Validator** | https://validator.schema.org | Comprehensive schema check |
| **Google Search Console** | https://search.google.com/search-console | Monitor indexing issues |

#### Validation Process

1. **Before deployment:**
   - Copy JSON-LD code to Google Rich Results Test
   - Fix any errors (red) and warnings (yellow)
   - Verify all required properties are present

2. **After deployment:**
   - Test live URL with Rich Results Test
   - Monitor Search Console for structured data errors
   - Check "Enhancements" reports in Search Console

### 9.8 Schema.org Don'ts

❌ **Never:**
- Use fake or inaccurate business information
- Include schema for content that doesn't exist on the page
- Use schema markup for hidden content
- Duplicate the same schema on multiple pages unnecessarily
- Use outdated or deprecated schema types
- Leave placeholder values like `[City]` in production code

✅ **Always:**
- Keep schema data consistent with visible page content
- Update schema when business information changes
- Use the `@id` property for cross-referencing between schemas
- Test changes before deploying to production

### 9.9 Schema.org Updates & Maintenance

Schema.org vocabulary evolves. Review and update structured data:

- **Quarterly:** Check for new schema types relevant to services
- **Annually:** Audit all pages for schema accuracy
- **As needed:** Update when business info changes (address, phone, services)

**Resources:**
- Schema.org Documentation: https://schema.org/docs/documents.html
- Google Structured Data Guidelines: https://developers.google.com/search/docs/appearance/structured-data
